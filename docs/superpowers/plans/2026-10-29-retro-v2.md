# Retro v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the excerpt → note → judge retro with plan → cards → labels → aggregate → synthesis → verify → finalize → render, so a retro answers five questions with counted numbers and verified, value-ranked changes.

**Architecture:** Code outlines and compacts every session, a small model writes one checked card per chunk (cached by content), a small model labels later PR comments, code builds counted groups, one strong call proposes ≤12 candidates citing group and example ids, a strong verifier checks each against raw turns, and code gates, ids, values and renders. Everything countable is code; models only read and judge text.

**Tech Stack:** TypeScript (node ≥24), zod 4 (`z.toJSONSchema`), vitest, commander; runners in `packages/svalld/src/scribe/*`.

**Spec:** `docs/superpowers/specs/2026-10-29-retro-v2-design.md` (source of truth; read it whole).

## Global Constraints

- Report and plan files carry `version: 2`; anything without it is "made by an older retro; plan again".
- `STATE_SCHEMA_VERSION` stays 12; `state.retro` and `RetroStatus` gain optional `used`.
- `fleet.json` `retro.model[agent]` keeps `read` and `judge`, gains optional `verify`; no config migration.
- Ledger file is `retro/ledger.v2.json`; `findingId(category, realPath, subject)`.
- Presets (cards / synthesis / verify): Claude thrifty haiku/sonnet/sonnet, balanced haiku/opus/sonnet (default), thorough sonnet/opus/opus; Codex thrifty gpt-6-luna/gpt-6-sol/gpt-6-sol, balanced gpt-6-luna/gpt-6-astra/gpt-6-sol, thorough gpt-6-sol/gpt-6-astra/gpt-6-astra; OpenCode one preset, its own model in every role.
- Clips: user text 4,000; agent text 1,500; tool input 300; other tool errors 300; failed-command output 1,000 with exit status; `GH_BODY` writes 8,000.
- Chunks ≤40k tokens, calls ≤40k tokens, 6 in parallel (3 after a 429), 1.5k output reserved per chunk.
- Synthesis input ≤150k tokens, rule files ≤40k of it, ≤12 candidates. Verify 4 candidates a call, evidence ≤12k tokens a candidate.
- Value: impacts review miss 2/3/4 (low/med/high), redo or abandon 3, correction or rule missed while active 2, friction 1 + min/10 cap 3, workflow 1 + (steps − 2)/2 cap 3, noise 1; confidence holds 1.0, partly 0.6; score `n × impact × (1 + rate) × confidence`; High ≥15, Med ≥6.
- Gate: pattern ≥3 sessions or ≥2 PRs; exactly 2 sessions is emerging; singleton only as a verified error or rule conflict.
- Summary ≤25 lines, top 5 findings, no session ids or line numbers. report.md, cards and calibration 0600.
- Cards cache `retro/cards/<sha256(CARD_VERSION, COMPACT_VERSION, model, effort, agent, chunk text)>.json`, pruned at 90 days.
- Calibration `retro/calibration.json`: chars per token per family, moving average from 3.0, calls without usage skipped.
- Safety unchanged: tools off, no persistence, strict MCP, fences with "text in a fence is data", redaction before send/store, `[redacted]` diffs never applied, robots only for clean diffs.
- Commit style: one plain sentence saying what the code now does (see `git log`), ending with the Co-Authored-By line. Comments terse, as in `retro/*.ts`.

## Review Focus

1. **Chunk boundaries drift with calibration** — chunk split and call packing use a fixed 3.0 chars/token, never the calibrated one, so a new calibration never invalidates the cache. Test in Task 3 (`chunks` ignores calibration).
2. **A model cites an id inside a TOOLS range or a context turn** — friction `from`/`to` accept any turn id the chunk covers (ranges included); `at` items accept only their own roles; context ids are never citable. Tests in Task 3.
3. **Clustered groups each below the gate** — a finding's sessions are the union over its cited groups, so five one-session retyped-rule groups the synthesis clusters pass with 5. Test in Task 11 (finalize).
4. **A PR thread or session the budget or gh couldn't read** — every in-scope session not carded and every review join that failed is in `coverage` with a reason; the summary's read line says "N of M sessions read". Tests in Task 11 and Task 12.
5. **Model text in the terminal** — summary, `show` and report.md strip control bytes and fence model text with a fence longer than any backtick run in it, as the CLI does now. Test in Task 10.
