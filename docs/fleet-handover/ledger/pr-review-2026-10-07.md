## High

**H1. Interrupt and carry sends one Escape; a working OpenCode needs two.** 93 / G high. Found in round 2 and probed live.
`packages/svalld/src/handover/rest.ts:69`, `:257`
- *Failure:* `ESCAPE = Buffer.from('\x1b')` is sent once to every agent kind. OpenCode 2.0.22 counts Escape presses
  with a 5 s reset and interrupts only on the second (`tui/src/component/prompt/index.tsx:503-533`). One press shows
  "esc again to interrupt" and the turn goes on. `rest.ts:166` then waits for the plugin's turn-over and returns
  agent_unsettled after settleMs. Each retry sends one more lone Escape at least 10 s later, outside the window.
  - Effect: Interrupt and carry, `--interrupt-after` and the CLI's `i` never rest a working OpenCode. With
    `--terminate-shells`, the agent and its server are SIGTERMed mid-turn instead.
  - `rest.test.ts:558-576` pins one `1b` as success, and the integration mock does not model interrupts.
- *Probe:* real 2.0.24 in a sandbox (private tmux socket, local fake model server). Two Escapes in separate send-keys
  calls 150 ms to 1 s apart interrupt; one call with two bytes does not. A blocked OpenCode (permission dialog) is
  interrupted by one Escape, as the code assumes.
- *Fix:* for opencode, send two separate Escapes about 200 ms apart. Fix the rest.test case and the mock. fixKind
  safe-correctness.

## Medium

**M1. A re-run rest forgets a lingering OpenCode server, and the export can race it.** 65 (panel probes 62 and 80) /
G high in round 1, medium in round 2 / S high, fix before merge. `packages/svalld/src/handover/rest.ts:389`, `:351`,
`:300`; `source.ts:313-322`, `:541-565`
- *Failure:* `layToRest` kills each window, then `gone(open.flatMap(… c.processes.agent?.server …))`. Here `open`
  holds only the windows live in this call. `source.rest.stopped` journals terminals only, and `terminated` is written
  after the settle wait and never read. Two triggers:
  - The daemon dies during the server wait.
  - `serversGone` throws "still runs after SIGKILL" and the user picks Resume.

  In both, the re-run Freeze finds no window, calls `gone([])` and exports while the old server may still write
  opencode.db. The destination then misses the tail. On abort, `revive()` reopens `opencode -s` beside the old server.
- *Calibration:* a live probe shows an idle server exits about 0.2 s after its window is killed (TUI finalizer
  SIGTERM→SIGKILL in 3 s; stdin EOF). So this needs a server stuck in shutdown plus a crash or failed SIGKILL during
  the wait. That is rare, but it breaks the spec's rule that the rest waits for or kills each server before the export.
- *Probe:* rest.test World, server lingering 60 s, crash at `source.rest.terminated:before`. The second
  `restTerminals` returns `{ok:true, terminals:[]}` with `opencode serve --stdio` alive.
- *Fix:* journal each server's pid/pgid/args with its terminal inside `source.rest.stopped`, before kill-window.
  - A re-run and the abort revive wait for, or kill, journaled servers still alive.
  - Match pid+args against the live table, never a blind pgid kill (pid reuse, reboot).
  - Persist the force-kill groups `serversGone` finds.

  fixKind safe-correctness.

**M2. A failed OpenCode import leaves the destination without its copy, and a forced record loses it.** 65 / G high.
Found in round 2 and probed. `packages/svalld/src/handover/sessions/opencode.ts:68-90`, `destination.ts:516-517`,
`:924-933`, `handover/service.ts:145-148`
- *Failure:* `dropSession` exports the held copy to `.here`, deletes `.here` in `finally`, then runs `session
  delete`. Nothing of the held copy survives if the import then fails (I/O, the 120 s timeout) or svalld dies between
  `destination.prepare.delete` and `.import`.
  - Source alive: a resumed prepare recovers (probed). After a plain import failure and an abort, though, the
    destination has no copy until the next successful handover.
  - Source then lost: `fleet recover --force-owner` goes through adopt → `supersede` → `discard`, which removes the
    stage holding the incoming export. The new owner holds neither copy, and `opencode --standalone -s <id>` opens an
    empty session that the plugin reports as started.

  Claude and Codex never have a moment with no copy, because `installSession` replaces atomically. The spec's
  force-owner text accepts losing work done on the lost machine, not the destination's own earlier copy.
- *Fix:* keep the held export outside the stage until the import succeeds. Re-import it when the import fails, and
  before discard/supersede/abort clear the stage. Add a forced-record test with an OpenCode scene. fixKind
  safe-correctness.

**M3. Jobs in OpenCode's terminal panes never block a rest.** 65 / G medium (both rounds) / S medium, fix before merge.
`packages/svalld/src/handover/processes.ts:104-116`
- *Failure:* OpenCode 2.0.22 turns session terminal panes on by default off Windows (`tui/src/config/index.tsx:324`).
  Their shells run under an `opencode-pty daemon` that the server spawns detached (`core/src/persistent-pty/daemon.ts:230-236`).
  - That daemon is a direct server child, so it counts as `served`.
  - The pane shell and its jobs sit in the server's `tree`, so they are never `strays`.
  - So `commands: []` (probed with ps rows), and an idle OpenCode rests (`rest.ts:162`) without the terminate choice.

  The job is then either killed by the server-tree kill or left writing the source worktree. Ruling R2 exempts MCP and
  language servers, not a job the user started in a pane. Panes are opt-in per session.
- *Fix:* count descendants of an `opencode-pty` child as commands. Blocking an idle pane shell too is the safe
  default. Add a fixture. fixKind risky-behavior-change.

**M4. A pending OpenCode /undo comes back to life on the destination.** 65 / G medium. Found in round 2, live probe of
import. `packages/svalld/src/handover/sessions/opencode.ts:60-64`
- *Failure:* /undo stages a revert. It sets `session.revert`, restores files, and the TUI hides later messages; they
  are deleted only when the next prompt commits it. The export carries `info.revert`, but import
  (`core/session/transfer.ts:89-143`) never writes it.
  - A handover between /undo and the next prompt lands with the undone turns live and no /redo.
  - Files lack those turns' edits, and the next prompt sends them to the model.
  - The fake stores the export verbatim, so no test sees it.

  R1 and handover.md:287 cover undo of pre-handover steps, not a staged undo turning into history.
- *Fix:* refuse to carry a session whose `info.revert` is set ("send a message or /redo, then hand over"). The dry
  preflight export then needs a temp file instead of /dev/null. Make the fake drop `revert` on import. fixKind
  safe-correctness.

**M5. The shared OpenCode service can resume a killed turn on the old source.** 60 / G high. Found in round 2, read
from OpenCode source. `packages/svalld/src/handover/rest.ts:169`, `source.ts:363-384`
- *Failure:* when Terminate and carry SIGKILLs a server mid-turn, the session keeps a durable claim (`time_suspended`,
  `core/session/execution.ts:75-88`). Standalone servers never sweep, and export does not carry the claim. But the
  managed `serve --service` resumes every suspended session at boot (`server/src/process.ts:105`,
  `execution/restart.ts:195-230`).
  - Effect: a later plain `opencode` on the old source starts the service and runs that turn in the stale copy, so an
    agent writes on the non-owner. The next hand-back then blocks.
  - Preconditions are narrow: terminate mid-turn, no service already running, plain opencode run outside Svall.
- *Fix (needs a Ruling):* at complete, delete the source's copy only for sessions terminated mid-turn (this
  conflicts with R1's "the source keeps its copy"), clear the claim, or document it beside the background-job
  limitation. fixKind risky-behavior-change.

**M6. The fault world never runs a live OpenCode agent.** 60. `packages/svalld/test/handover/fault-world.ts:308-337`,
`faults.test.ts` REACH
- *Failure:* cy is dormant and not among settledOn's windows (`:798`). So no crash case strikes the plugin-reported
  interrupt, the server wait, the journal+SIGKILL in `serversGone`, the survivor error, or activating `opencode -s`.
  `source.rest.terminated` and `forcekill` share names with the shell path, so the every-failpoint check passes
  without the server path. M1 survived 1345 green cases because of this.
- *Fix:* give one character a live OpenCode with a lingering server, add it to settledOn, and give the server kill
  its own failpoint names. fixKind safe-correctness.

**M7. The OpenCode adapter's data-safety guards have no test.** 70 (mutations) / G medium. Found in round 2.
`packages/svalld/src/handover/sessions/opencode.ts:77`, `:62`, `:8`; `destination.ts:513`
- *Failure:* each mutation below passes every svalld/cli suite and 1345 fault cases:
  - `i < incoming.length && incoming[i] !== id`: deletes a longer destination copy. This is the only guard for
    destination-only turns.
  - `resumeFolder(c, undefined, …)`: terminal 2's session is imported into terminal 1's folder, and `-s` resumes in the
    stored directory.
  - Dropping `--standalone` from the source export: the export goes through the user's shared service. The fake strips
    the flag before parsing.
  - `SESSION = /^.+$/`: removes the only check on ids that come from the peer's manifest.
- *Fix:* add a sessions.test case for held [m0,m1,mX] against incoming [m0,m1], a destination test with an OpenCode
  second whose cwd differs, and make the fake refuse session commands without `--standalone`. Add malformed-id cases.
  fixKind safe-correctness.

**M8. The OpenCode CLI timeout sends SIGTERM once and never settles.** 50 / G medium. Found in round 2 and probed.
`packages/svalld/src/handover/sessions/registry.ts:181-193`
- *Failure:* `spawn({timeout})` signals once, and the promise resolves only on `close`. A CLI that ignores SIGTERM or
  sits in D state never settles. Every destination and source RPC runs through `serial()`, so prepare, abort, complete
  or freeze queue behind it until svalld restarts. The probe's SIGTERM-ignoring fake was still running minutes later.
  `runChild` and `runProcess` escalate.
- *Fix:* SIGKILL a few seconds after the deadline and reject at the deadline as a SessionError. Add a test with a
  SIGTERM-ignoring fake. fixKind safe-correctness.

**M9. A blocked OpenCode prepare has already rewritten the destination's plugin log.** 45 / S medium.
`packages/svalld/src/handover/destination.ts:484-493`
- *Failure:* `installSession` writes the incoming `.jsonl` before `importSessions` runs the DB prefix check. A copy
  continued with plain `opencode -s` leaves the log untouched, so the log is replaced. The DB check then blocks, and
  the log and DB describe different conversations.
- *Fix:* run the prefix check, as a dry export compare, before installing the log. Do not delete the DB copy before
  the staged files are validated (sol). fixKind safe-correctness.

**M10. With handover off, an exited OpenCode second terminal goes dormant and reopens its session.** 50 / G medium in
round 1, low in round 2 / S medium. `packages/svalld/src/dormancy.ts:47-50`, `fleet/control.ts:101`
- *Failure:* `loseSecond` keeps any second with `c.second.agent` dormant. OpenCode sends no SessionEnd, so the agent
  clears only after two shell polls (about 3-6 s). Quit `opencode` in terminal 2 and `exit` at once: the second keeps
  `opencode -s ses_…`, and the next show of terminal 2 resumes the closed session where main gave a fresh shell. No API
  drops a dormant second. Probed.
- *Fix:* tell an agent Svall stopped, or one a crash cut off, from one the user already exited. Keep the last process
  evidence, or check the agent pid is alive, on a user window close. sol notes `reviveCommand(c.second)` alone does not
  fix it, and requiring a live agent everywhere would lose R4's crash recovery. Add a quit-then-exit test. fixKind
  safe-correctness.

**M11. An agent interrupted during a frozen window is not resumed after abort or a late activation.** 45 / G medium in
round 1, low in round 2 / S medium. `packages/svalld/src/handover/source.ts:576-579`, `fleet.ts:583-584`,
`destination.ts:577-581`, `handover/service.ts:145-148`
- *Failure:* `resumeInterrupted` runs only at start (`main.ts:222`) and only when writable. Suppose a source reboots,
  or loses tmux, during a freeze:
  - Reconcile marks the working agents interrupted.
  - After an abort, `release` runs activate + reconcile and nothing else.
  - Those characters stay dormant until a later restart resumes them unasked.

  The same holds for a carried genuine crash mark and for recovery by adopt.
- *Fix:* call `fleet.resumeInterrupted()` after `reconcileNow()` on the three paths. Not inside startup's
  `adoptAtStart`, which runs before the hook receiver (`main.ts:176` vs `:220`); main's own call at `:222` covers
  startup. fixKind safe-correctness.
