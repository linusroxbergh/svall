Build:
1. An `opencode` session adapter. Source: after the agent is rested, `opencode session export --standalone <id>` into the handover's staging area; that JSON is the session's carried file (byte for byte, hashed and transferred like Claude/Codex files). Respect the data dir env (`XDG_DATA_HOME`, `OPENCODE_DB`) the way Claude/Codex honour CLAUDE_CONFIG_DIR/CODEX_HOME. A missing session (export exits non-zero / "Session not found") is a preflight blocker like a missing required file.
2. Destination, before activation: `opencode session delete --standalone <id>` if the id exists (stale copy from an earlier handover; ignore "Session not found"), then `opencode session import --standalone --directory <terminal cwd> <file>`; succeed only if stdout contains `Imported session: <id>` (import exits 0 on "Session already exists"). Never let a terminal revive with `-s <id>` when the import failed — `-s` on a missing id silently creates an empty session. Make it idempotent and crash-safe across a retried prepare/commit the way the other adapters' destination steps are (check the journal/failpoint pattern; add failpoints for the new steps if the others have them, and the fault suites must cover them).
3. Revive: `opencode --standalone -s <id>` plus the launch flags an idle close keeps (main's `withStandalone`/`withoutV1Flags` in fleet.ts and dormancy.ts already build OpenCode revive commands — reuse, don't duplicate). transcriptPath/session record on the destination per what OpenCode records (check what main stores in agent.transcriptPath for OpenCode; if none, record what the destination needs).
4. The agent probe in registry.ts (`probeAgent`): for opencode on the far machine — installed and version >= 2.0.22, logged in (whatever main's doctor uses for OpenCode login; `auth list --standalone`), and "hooks" = Svall's OpenCode plugin installed (~/.config/opencode/plugins/<svall plugin>, see main's opencode install code). Add 'opencode' to HANDOVER_KINDS; agentBlockers stops refusing it.
5. Tests proving an OpenCode character hands over Mac→Linux and back in the same handover tests where Claude and Codex characters do (use a fake `opencode` binary like the fake claude/codex the tests use, implementing export/import/delete with the real exit-code/stdout behaviour from the spike, including "already exists" exit 0 and "-s on a missing id" semantics).
