## Security
F1 (I9, high) scripts/release/allowed_signers:11 — the all-zero placeholder is a small-order Ed25519 key: `ssh-keygen -Y verify` accepts forged signatures (verified on OpenSSH 10.3p1 and 9.6p1; verifyRelease accepted a forged release `evil-1`), and every release ships it. Ship a comment-only allowed_signers (ssh-keygen refuses it, exit 255) so verification fails closed until the owner provides the real release key; add a release test that fails on an all-zero or placeholder key.
F2 (D10, high) packages/cli/src/controller/install.ts:46/118 — a `--release` archive counts as signed when a SHA256SUMS.sig member exists; the far first install verifies against the archive's own allowed_signers. Verify on the Mac before upload: unpack, verifyRelease + sshVerify against the controller's own allowedSigners(), and set `signed` from that result.

## SSH transport and the helper
F3 (D3, high) packages/cli/src/controller/ssh.ts:115/196-200 — masters are shared across processes through the socket path; a second process adopts a live master and its close() sends `-O exit`, killing the app's forward, terminals and any in-flight run (reproduced). Stop sharing masters between processes (per-process control socket, or never adopt a socket this process did not spawn); close() exits only a master this process owns; connectRemote cancels its forward when its client closes.
F4 (D21, medium) packages/cli/src/commands/host.ts:53 — `archi host …` has no SIGTERM/SIGINT/SIGHUP handler, so the app's Stop orphans the master. Close open masters on those signals, then exit (any command that opens a master).

F6 (D20, controller fold-in) packages/cli/src/controller/connection.ts:183 — the gateway client's `timeout` frame is `unreachable` like `disconnected`; test it.
F7 (D17, medium) packages/cli/src/commands/connect.ts:41 — the helper loads the registry once; reload it on each resolution (or when a looked-up machine id is missing).
F8 (G14, low) packages/cli/src/controller/connect.ts:51 — announce() returns LOCAL when route.ownerMachineId === registry.localId.
F9 (17a carried minors) remote goOnline spawn rejections are `other` (helper idles) and SshMaster.spawn classifies a master dying with empty stderr during open as `other`; both are transport failures → `unreachable`.

F26 (I4, medium, ruling) — the app runs `archi host add` with no tty, so step 1's host-key/password prompt fails 255. When stdin is not a TTY on macOS, the interactive probe sets SSH_ASKPASS to a small helper shipped in the release (osascript dialog; hidden answer for passwords) with SSH_ASKPASS_REQUIRE=force, so the user answers in a dialog. Keep it to that probe.

The app UI does not change.

## From the M2 on-machine pass (m2-onmachine-report.md)
F28 (on-machine defect 4 + D18, high) apps/desktop/mac/Sources/Archipelago/SurfaceManager.swift:152-157 — after a dropped master, rebuild() re-runs each stored attach, but tmux has already destroyed the `v-<id>` viewer sessions (`destroy-unattached on`, packages/archid/src/tmux/tmux.ts:73), so all twelve print "can't find session"; a fresh term.attach works. The owner-change closeAll (RemoteConnection.swift:99) likewise destroys surfaces without telling the page, which then sends term.show with no attach forever. Fix both the same way: a remote surface that must be rebuilt, or is closed by an owner change, is reported to the page (term.exited or equivalent) so the page issues a fresh term.attach through the daemon; test the rebuild and owner-change paths at the decision point.
F29 (on-machine defect 5, minor, fold-in) packages/cli/src/controller/connect.ts:79 — the tick checks only `master.check()`, so a forward cancelled while the master lives goes unnoticed (75 s, no event). Have alive() also confirm the forward's local port accepts a connection.
