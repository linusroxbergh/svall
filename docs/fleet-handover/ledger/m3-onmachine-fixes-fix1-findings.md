# O-wave fix round 1 — findings (binding)

1. (Important) O6 blocks kept worktrees whose commit does come back. git-repair.ts:67-72 (`reaches`) and :97-104 judge reachability with the destination's own objects; source tips the destination has never seen are dropped by `--ignore-missing`, so when every tip that reaches C has moved to a commit unknown here, C counts as lost though the returning store holds it (`git rev-list --ignore-missing -n 1 C --not <unknown child of C> main --` prints C). Ordinary case: a kept worktree on branch B at C, with B advanced on the other machine; or one detached at an old main commit after a pull plus commits there. The message ("no branch, tag or HEAD the handover brings back reaches it") is then false. Fix: let the side that holds every tip decide — e.g. inspect reports the kept commits it could not prove reached, and the controller asks the source daemon to run `rev-list <C…> --not <refs>`; block only on what the source cannot reach. Test: the kept worktree's branch advances on the other side and the round trip passes; a commit the returning store truly lacks still blocks.

2. (Important) O1's same-id case never finishes a half-done provision. provision.ts:93 with host.ts:604: the created path writes fleet.json and setup (lines 82-84) before `daemon-reload` and `enable --now`; if systemctl fails or the 120 s ssh times out, a rerun finds the same id, returns `held` and reports success with the unit never started — the handover then fails at connection-info as daemon_down. Ruling: "same id: nothing to do" meant no re-key; the spec's "Repeated setup is idempotent" means a rerun converges — in `held`, run ensureUnit then `enable --now` (both no-ops when already right). Also report a refusal (ProvisionRefused) distinctly (its own exit code or JSON error) and show the "move that fleet home aside" action only for it — not for timeouts, a companion too old to have `fleet provision`, or a far fleet in use. Update the held test to expect `enable --now`.

3. (Minor, promoted) `tips` (protocol/src/handover.ts:245,270) is a plain z.string() array whose entries go into git argv before `--` (git-repair.ts:70); an entry starting with `-` is read as an option. Ruling: promoted — wire input reaching a subprocess's option position fails open against the argv-only rule — validate as a full hex object name (40 or 64 hex chars).
