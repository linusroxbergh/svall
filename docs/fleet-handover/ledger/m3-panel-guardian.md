# M3 panel — The Guardian (7 findings; paths under the impl worktree)
G1 high error-handling — packages/archid/src/main.ts:81 — a running daemon never learns a gateway named after it started: gateway/authority are built only when config.gatewayMachineId was set at start, source.ts:332 blocks when !this.d.authority, and enableHost (cli controller/host.ts:578) only rewrites fleet.json — so after `archi host enable` (or the app's "Make it this fleet's gateway") the first handover is blocked at preflight with "this fleet names no gateway" until archid restarts, with nothing telling the user. Fix: resolve the authority per call from current config, or have host enable notify/restart the daemon.
G2 medium security — archid ownership/guard.ts:74 — phone sockets can call every handover 'transaction' RPC (and 'read' handover.inspect); only 'recovery' is app-only. A phone login can abort a running freeze, open a destination journal with a crafted prepare, seal source replicas via complete with a crafted landed, trigger full-fleet hashing/probe writes; phones get tx ids/generations from broadcast handover.changed events; spec: phone-initiated handover not in v1. Fix: refuse 'transaction' methods and handover.inspect for caller !== 'app'; phone-viewer test.
G3 medium security — cli controller/handover.ts:482 — session file paths escape the stage: entries() does path.posix.join(stage(i), f.path) and join(s.sourceHome, f.path), collapsing `..` before transfer.ts pathProblem sees it; on a pull a far source's manifest naming `../../../../.zshrc` makes the controller's rsync (--mkpath) write outside the stage on the Mac. installSession's check runs only at prepare. Fix: reject any f.path relativeProblem refuses before joining.
G4 medium security — archid handover/destination.ts:191 — claim reserves/creates roots at manifest paths never checked against path roots (only rootProblem + fleet-home clash); manifestProblems/within(root.dir) run only at prepare, after files landed (e.g. ~/Library/LaunchAgents/x.plist on a pull). The controller's freeze check (handover.ts:374) never compares m.destinationRoots/root destinationPaths with the pathRoots it sent. Fix: controller requires them equal; run manifestProblems in runClaim first.
G5 medium error-handling — cli controller/handover.ts:416 — the controller's rsync is first checked after Freeze rested every terminal: resolveRsync only inside transfer(); preflight probes neither local nor far rsync; build-companion ships no bin/rsync, so a controller on the Linux gateway (or a checkout without the vendor build) rests the fleet then stops. Fix: probe local and far rsync in preflight (rsync_unsupported); on Linux accept the system rsync when rsyncVersion passes.
G6 low security — archid handover/git-repair.ts:80 — repair writes `.git` gitfiles and registration `gitdir` through symlinks carried in (writeFileSync follows links). Fix: refuse when not a regular file, or temp+rename.
G7 low type-safety — archid gateway/client.ts:123 — the ssh gateway answer is cast unchecked; a malformed frame surfaces as TypeError/ZodError, which HandoverService.relay treats as "no gateway answered" and adopts the relayed record. Fix: zod-parse the frame; anything else is AuthorityFailure('invalid_request').
